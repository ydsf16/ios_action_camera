# 拍摄控制、分享与 10× 变焦

## 本轮实现

- 保留默认 ≤5 ms 曝光与拍摄结束后的既有流程，不自动打开原片。
- 通过 AVCaptureEventInteraction 接入系统拍摄按键：松开一次开始录像，再一次停止；忽略 began 和 cancelled。仅在拍摄页、App 活跃且可录制/正在录制时启用，设置、素材、提示框与收尾阶段禁用。
- iOS 17.2 起启用标准按键接口；iOS 17.0/17.1 继续使用屏幕按钮。
- iOS 18+、支持 Camera Control 的设备注册变焦控件与必需的 controls delegate。数值使用和屏幕滑条一致的显示倍率及设备上限；设备/格式重新配置时重建控件，普通变焦不重新启动相机或重置时钟。
- 播放页增加系统分享入口，分享当前选中的原片或稳定结果，无需先写入相册。生成中禁用，避免共享正在替换的输出。
- 拍摄变焦上限从 5× 调整为 10×，仍按物理设备/格式限制取较小值。稳定裁切上限仍是 5×，二者相互独立。

## 外接控制兼容性

| 设备 | 接入路径 | 验证情况 |
| --- | --- | --- |
| iPhone 音量键 | 系统 AVCaptureEventInteraction | 已实现，待真机按键验收 |
| iPhone Camera Control 按下/滑动 | 系统拍摄事件 / AVCaptureSlider | 已实现，待真机验收 |
| iOS 26 + 支持遥控拍摄的 H2 AirPods | 用户在系统设置配置遥控拍摄后，复用标准拍摄事件 | Apple 文档支持，尚未配件实测 |
| 普通蓝牙自拍遥控器 | 取决于其发送的 HID/按键事件能否被系统识别 | 未取得型号，不保证兼容 |
| 专有蓝牙手轮、云台、拍摄手柄 | 需要具体产品的协议或 SDK | 尚未实现，等待品牌型号 |

未加入音量变化监听、隐藏音量控件、私有 API 或猜测的蓝牙协议。Camera Control 的滑动变焦不能代表专有蓝牙手轮已获得支持。

## 依据

- [Apple AVCaptureEventInteraction](https://developer.apple.com/documentation/avkit/avcaptureeventinteraction)
- [WWDC25 Capture Controls](https://developer.apple.com/videos/play/wwdc2025/253/)

## 验收

- CaptureCore 测试覆盖双摄显示倍率到设备倍率映射、10× 上限、受限硬件、长焦倍率与对数滑条；29 项通过。
- iPhone 真机尚未测试：音量上下键单击/长按/取消，设置或素材页面恢复普通音量，AirPods/其他遥控器，Camera Control 滑动与双指变焦数值同步，10× 时录制内参/IMU/帧率不受影响。
- 分享待验证：原片与稳定版分别打开系统分享面板，取消分享、实际接收的视频尺寸/帧率/声音与所选文件一致。
- 本轮代码已于 2026-09-18 安装并启动于 iPhone 16 / iOS 18.2.1；未上传，正在审核的构建不受影响。

## 2026-09-18 真机观察

- 签名 Release 构建成功，覆盖安装并启动成功；安装前的 6 段素材仍在，未删除素材或改写原始数据。
- 新采集的 10× 短片：4K HEVC 原片 124 帧，2.8K H.264 输出 124 帧，视频 PTS 和帧时长逐项一致，音轨均保留。124 帧都有有效内参；设备倍率 20 × 显示换算 0.5 = 10×。处理耗时 1.59 秒。
- 第二段 0.5× 短片：228 帧输入及输出、3.82 秒原片，处理耗时 2.78 秒；音视频时长保持一致。
- 两段均有 2 条开头 FrameWasLate 记录（其中一条在首个保存帧之前）。这不是零丢帧验收；仍需更长录制判断稳态帧率。
- Xcode 真机截屏观察到系统 Camera Control 变焦面板（9×），说明控件已在设备上显示。实际音量键行为、前后台恢复和分享操作的用户确认仍待收集；不能由文件结果推定全部 UI 测试通过。
- 本机 iOS 18.2.1 无法验收 iOS 26 AirPods 遥控。其他蓝牙配件仍缺少型号和设备。
