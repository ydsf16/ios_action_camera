# 边录边稳定：设计提案

## 目标

录制停止后只需处理少量尾帧并封装音频，让用户尽快得到可播放的稳定视频。当前实现仍为拍后处理，本方案尚未接入生产录制链路。

## 当前阻碍

现有 StabilizationInput 从已完成的录制包加载数据，Gyroflow 在创建引擎时计算整段姿态、平滑和裁切。当前的双向平滑与动态裁切会利用未来运动信息，尚不能直接向引擎持续追加采集数据。单纯允许处理队列在录制时运行只能处理旧素材，不能提前完成正在拍摄的片段。

## 分步实现

1. 独立实现有界时间窗的姿态与裁切计算，允许数秒延迟。先在既有素材上模拟逐帧输入，对比完整离线结果，确认延迟、边界连续性、水平锁定和裁切表现。
2. 采集层把原片、IMU 和内参继续完整落盘；流式处理作为可放弃的消费者，绝不阻塞采集队列。复用像素缓冲及 Metal 路径，限制帧缓存和在途编码数量。
3. 优先覆盖默认 4K60 → 2.8K60；对变焦、镜头切换、横竖方向、时间轴及音频分别做契约验证。禁止用删帧来维持看似实时的输出。
4. 原片写入和稳定输出会并发使用编码及内存资源，需要在真机上测量。队列超限或持续落后时，结束本次流式尝试，保留完整原片，自动回退拍后处理。
5. 停止录制后补齐 IMU 尾部与平滑窗口，处理剩余帧、完成音频封装，校验后原子发布成片。处理中途退出前台时沿用可恢复任务的策略。

## 产品取舍

首版不承诺“停止即成片”，也不要求实时稳定预览。采用固定延迟意味着与整段离线双向平滑结果可能不同，尤其是长时间强力平滑、水平锁定和快速变焦。保留原片，用户仍可在拍后改变参数重新生成。

## 验收门槛

- 同一真机、相同 4K60 素材与 2.8K 输出，记录停止后等待、全程吞吐、帧数/PTS、声音、温度和峰值内存。
- 与采集独占模式比较丢帧；并发处理不得破坏 IMU 时钟映射或轴向。
- 覆盖静止、走跑、急转、动态变焦与跨镜头；检查窗口交界处的跳动和动态裁切抽动。
- 验证短于窗口的录像、60 秒自动停止、后台退出、资源超限与拍后回退。
- 完成这些验证后再决定是否默认开启，不能以模拟器或 GPU 已启用作为通过依据。
